# ad-spy — разведка по видеорекламе конкурентов

Четыре стадии: **собрать → скачать → разобрать → сделать выводы**. Первые три
делают скрипты и выдают только факты. Четвёртую делаешь ты по фактам и кадрам.

Скилл отвечает за источники, добычу и препарирование. Глубокая стратегия по
скрипту — у **video-ad-analyzer**, превращение находок в собственные ролики —
у **storyboard-video-engine**. Не дублируй их, передавай работу.

## Проверка среды

Нужна неограниченная сеть и Chromium. В песочнице claude.ai прокси не пускает
к facebook.com и ads.tiktok.com — если сбор возвращает ноль и в `raw/` пусто,
скажи пользователю, что это надо запускать в Claude Code или Cowork на его
машине, и не ищи обход.

Один раз за сессию:

```bash
python3 scripts/adspy.py selftest
```

Чего не хватает — ставь сам, не отправляй пользователя это делать:

```bash
pip install playwright faster-whisper && python -m playwright install chromium
brew install ffmpeg tesseract      # Linux: apt install ffmpeg tesseract-ocr
```

`playwright` и `ffmpeg` обязательны. Без `faster-whisper` не будет транскрипта
(разбор пойдёт по кадрам и суперам), без `tesseract` не будет OCR суперов.

## С чего начать: что дал пользователь

| Дано | Что делать |
|---|---|
| Название бренда | `run "Nordace" -s meta` — поиск по ключевому слову в Ad Library |
| Ссылка на FB-страницу | достань `page_id` из библиотеки и передай его цифрами — точнее поиска по слову |
| Готовый URL Ad Library с фильтрами | передай URL целиком как query, он пойдёт как есть |
| Ниша, а не бренд | `-s tiktok` (Creative Center = топ по нише) + `-s meta` по 2–3 ключевым словам |
| Только страна ЕС | `-s tiktok-library` — там есть даты показа и охваты |
| Ссылки на конкретные ролики / профиль в TikTok | это не библиотека рекламы, это органика → **tiktok-grab** / **yt-grab** |

Спрашивай страну, если её нет: `-c US` по умолчанию, а выдача Ad Library
по странам различается радикально.

## Полный проход

```bash
python3 scripts/adspy.py run "Nordace" -o ~/spy/nordace -n 40 --min-days 14
```

Разложено по стадиям (запускай так, когда падает одна из них):

```bash
python3 scripts/spy_sources.py "Nordace" -s meta -o ~/spy/nordace -n 40 -c US
python3 scripts/spy_fetch.py   -o ~/spy/nordace --min-days 21 --min-variants 2 --thumbs
python3 scripts/spy_dissect.py -o ~/spy/nordace --lang en --ocr-lang eng
python3 scripts/spy_report.py  -o ~/spy/nordace
```

Ключевые флаги: `-n` сколько объявлений собрать, `--min-days N` и
`--min-variants N` — не качать то, что запустили вчера, `--headful` когда
библиотека просит логин или показывает капчу, `--state s.json` чтобы
залогиниться один раз и переиспользовать сессию.

## Что вообще значит «активное»

Публичные библиотеки не отдают ни CTR, ни расход. Единственный объективный
сигнал окупаемости — **срок жизни**: убыточный креатив выключают за считанные
дни, поэтому объявление, крутящееся третий месяц, окупается почти наверняка.
Второй сигнал — **количество вариантов** в связке (`variants`): много вариантов
= на креатив льют бюджет и тестируют его вширь.

Отсюда статусы в `facts.md`: `эвергрин` (60+ дней), `проверено` (21–59),
`в тесте` (7–20), `свежий тест` (<7), `+ масштаб` при 5+ вариантах.
Разбирать в первую очередь эвергрины и «проверено + масштаб» — на свежих тестах
конкурент сам ещё не знает, работает оно или нет.

TikTok Creative Center дат показа не отдаёт, зато отдаёт CTR и лайки — там
сигнал другой, и сравнивать напрямую с Meta нельзя. Скажи об этом в разборе.

## Стадия 4 — разбор (это делаешь ты)

Скрипты кладут в папку проекта:

```
ads.json             все объявления с метаданными и статусами
ads.csv              то же таблицей, отсортировано по сроку жизни
facts.md             лидерборд, что появилось, что выключили, профиль продакшна, все крючки
analysis_input.json  компактный бандл: факты + транскрипты + супера + пути к кадрам
media/               видео          frames/<ad_id>/       кадры (плотно по 0–3 с)
dissect/             полный разбор  frames/<ad_id>-sheet.jpg  контактный лист
raw/                 сырые ответы библиотек
```

Порядок работы:

1. Прочитай `facts.md` — он задаёт, кого вообще стоит разбирать.
2. Прочитай `analysis_input.json` — один файл вместо десятков.
3. **Посмотри контактные листы** через Read: `frames/<ad_id>-sheet.jpg`. Кадры
   идут слева направо по времени, таймкоды каждой ячейки — в `frames` внутри
   бандла. Первый ряд — это hook-окно. Без просмотра кадров визуальную часть не
   пиши: транскрипт не показывает, кто в кадре, где продукт и как снято.
4. Разбор каждого ролика и кросс-анализ веди по `references/analysis-framework.md`
   и пиши в `REPORT.md` в папке проекта.
5. Стратегию по скрипту (крючки, TOF/MOF/BOF, углы) отдавай **video-ad-analyzer**:
   у него зашита экспертиза, повторно её не изобретай.

Не пересказывай `facts.md` — на него ссылайся. Ценность разбора в том, чего
в цифрах нет: что за приём в первые 3 секунды, почему он держит, какой угол
продаёт и чего конкуренты не делают вообще.

## Мониторинг

Повторный `run` по той же папке — это слежение. Новые объявления допишутся,
пропавшие из библиотеки попадут в `facts.md` как выключенные, у остальных
подрастёт `days_active`. Раз в неделю по нише — и видно, что конкурент
масштабирует, а что убил. Для расписания предложи **/loop** или Routine.

## Передача работы

- Скрипт, структура, углы, funnel-логика → **video-ad-analyzer**
- Посекундный разбор одного ролика целиком → **video-analysis** (нужен ARK_API_KEY)
- Органика конкурента, не реклама → **tiktok-grab**, **yt-grab**
- Найденное превратить в свои сториборды и клипы → **storyboard-video-engine**
- Промпты под генерацию видео → **video-gen-prompter**

Если пользователь просил «разбери конкурентов», а не «скачай» — прогоняй всю
цепочку сразу и отдавай разбор, а не папку файлов.

## Что говорить в ответе

Где лежит папка, сколько объявлений активно и сколько разобрано, кто в топе по
сроку жизни, 3–5 паттернов и что из этого забирать в тест. Ссылайся на
`facts.md` и `REPORT.md`, полные таблицы в чат не вываливай. Провалы —
отдельным списком с причиной.

## Границы

- Работаем только с публичными библиотеками прозрачности рекламы. Логин-гейты,
  приватные аккаунты и платные API конкурентов не обходим.
- Чужие ролики — материал для анализа, не для использования в своих креативах.
  Если пользователь хочет вставить кусок чужого видео к себе — предупреди про
  права один раз и оставь решение ему.
- Не долби библиотеку: `--sleep`, разумный `-n`, повторные прогоны раз в день,
  а не раз в час.

## Если что-то сломалось

Сбор вернул 0, а в `raw/` лежат ответы → библиотека переименовала поля.
Открой любой файл из `raw/`, найди узел объявления и поправь экстрактор в
`scripts/spy_sources.py` — сбор переписывать не нужно. Остальное:
`references/harvesting.md`.

## Справочники

- `references/sources.md` — какие библиотеки существуют, что каждая отдаёт, параметры URL
- `references/harvesting.md` — как устроен перехват, логин, капчи, починка экстракторов
- `references/dissection.md` — что значит каждая метрика разбора, ffmpeg-рецепты, транскрипт и OCR
- `references/analysis-framework.md` — как из фактов делать выводы + структура REPORT.md
- `references/output-schema.md` — поля ads.json, dissect/*.json, analysis_input.json
