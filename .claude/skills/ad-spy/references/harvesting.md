# Сбор: как устроен перехват и что делать, когда он ломается

## Почему перехват, а не запросы к API

У библиотек рекламы нет открытого API для коммерческих объявлений. Их фронтенд
ходит в подписанные внутренние эндпоинты, и подпись меняется. Реверсить её —
значит чинить скилл каждый месяц.

Поэтому `spy_sources.py` открывает публичную страницу библиотеки в Chromium,
подписывается на события `response` и читает **ответы, которые страница
получила сама**. Подписывает запросы её собственный JS. Пока библиотека
открывается в браузере — сбор работает.

Дальше вместо разбора по фиксированным путям (`data.ad_library_main.
search_results_connection.edges[0]...`) идёт рекурсивный обход всего JSON:
берём каждый вложенный словарь и проверяем, похож ли он на объявление
(`adArchiveID` + `snapshot`). Перестановка полей внутри ответа сбор не ломает.

## Пагинация

Бесконечная лента: скролл вниз, ожидание, проверка прироста. Останов — когда
набрали `-n` или четыре прокрутки подряд не дали новых объявлений
(`--scroll-pause` увеличивает паузу на медленной сети).

## Логин, капча, регионы

Библиотеки открываются без логина, но при подозрительном трафике Meta
перекидывает на проверку. Тогда:

```bash
python3 scripts/spy_sources.py "Nordace" -o ~/spy/n --headful --state ~/.adspy/meta.json
```

Окно откроется, пройди проверку руками — сессия сохранится в файл состояния и
следующие прогоны пойдут в фоне с тем же `--state`. Если библиотека сразу
редиректит на `/login` или `/checkpoint`, скрипт скажет об этом прямо.

Выдача зависит от страны запроса и от `country` в URL. VPN менять не нужно,
но если результаты пустые для нишевого рынка — попробуй `-c ALL`.

## Дедупликация

Внутри одного прогона объявления схлопываются по ID библиотеки. Между
прогонами `merge_into` обновляет уже известные записи, сохраняя
`first_captured_at`, `seen_runs` и всё, что наработано локально (`local_video`,
`dissected`). Одинаковые ролики под разными ID схлопываются позже, на скачивании,
по md5 файла — второй раз такой ролик не качается и не разбирается.

## Починка экстрактора

Симптом: `0 объявлений при N перехваченных ответах`. Значит, поля переименовали.

```bash
ls ~/spy/brand/raw/                                  # сырые ответы этого прогона
python3 -c "import json;d=json.load(open('~/spy/brand/raw/meta-...-000.json'));print(json.dumps(d)[:3000])"
```

Найди в JSON узел одного объявления, посмотри, как теперь называются ключи, и
допиши алиасы в `is_meta_ad` / `norm_meta` (там везде `_first(d, "новое",
"старое")` — добавление алиаса не ломает старый формат). Ничего, кроме
экстрактора, править не нужно.

## Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| 0 объявлений, `raw/` пуст | нет сети до библиотеки или редирект на логин | проверь среду; `--headful`, посмотри, что в окне |
| 0 объявлений, `raw/` полон | сменились имена полей | чини экстрактор, см. выше |
| Собирается 8–12 и встаёт | лента не догружается | подними `--scroll-pause` до 4–5 |
| `video_url` пустой у половины | это карусели и статика | ставь `--media video`; графику скилл не разбирает |
| Прогон падает на playwright | не поставлен браузер | `python -m playwright install chromium` |
| Много объявлений чужих брендов | поиск по слову | ищи по `page_id`, см. `sources.md` |

## Нагрузка

Один прогон — это одна вкладка и десяток скроллов, столько же делает человек.
Не гоняй сбор в цикле, не поднимай `-n` до сотен без нужды и держи повторные
прогоны на дистанции в сутки. Мониторинг ниши раз в неделю даёт ровно ту же
картину, что и ежечасный, и не выглядит как атака.
